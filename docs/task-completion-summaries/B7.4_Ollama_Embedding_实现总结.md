## 🔑 关键设计解读

### Q1: 为什么要支持双端点（OpenAI 兼容 + Legacy）？
**解释：** Ollama 早期版本使用 legacy API 格式（`/api/embed`），新版本支持 OpenAI 兼容格式（`/v1/embeddings`）。为确保向后兼容，代码优先尝试 OpenAI 格式，失败时降级到 legacy 格式。

**好处：**
- 支持所有版本的 Ollama
- 用户无需升级即可使用
- 自动适配，无需配置

### Q2: 为什么需要模型维度验证？
**解释：** 每个嵌入模型的输出维度是固定的（如 nomic-embed-text 是 768 维）。如果用户配置错误的维度，会导致向量存储和检索出现问题。维度验证可以在初始化时发现问题并给出警告。

**好处：**
- 提前发现配置错误
- 避免后续向量操作失败
- 提供清晰的问题定位

### Q3: 连接失败为什么要提供两个命令？
**解释：** Ollama 是本地服务，最常见的错误是：1) 服务未启动，2) 模型未下载。提供这两个命令可以帮助用户快速解决这两个问题。

**提供命令：**
- `ollama serve`：启动 Ollama 服务
- `ollama pull {model}`：下载指定的模型

**好处：**
- 减少 user confusion
- 提高问题解决效率
- 改善用户体验

## 🔧 使用示例

### 基本使用
```python
from src.libs.embedding.embedding_factory import EmbeddingFactory

# 加载配置
settings = load_settings()

# 创建 Ollama Embedding
embedding = EmbeddingFactory.create(settings)

# 批量向量化文本
texts = ["Hello, Ollama!", "How are you?"]
result = embedding.embed(texts)

# 访问结果
print(f"Generated {len(result.embeddings)} embeddings")
print(f"Dimension: {result.dimension}")
print(f"First embedding: {result.embeddings[0][:5]}...")  # 前5个值
```

### 配置示例
```yaml
# config/settings.yaml
embedding:
  provider: ollama
  model: nomic-embed-text
  dimension: 768
  batch_size: 32
```
