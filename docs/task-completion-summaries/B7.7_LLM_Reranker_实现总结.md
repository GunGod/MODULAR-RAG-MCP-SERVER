## 📁 创建的文件

### 1. `config/prompts/rerank.txt`
**作用：** LLM 重排序的 Prompt 模板文件

**关键内容：**
- 结构化的 Prompt 模板，包含占位符 `{query}` 和 `{chunks}`
- 定义任务：相关性排序专家
- 输入格式：query + retrieved chunks
- 输出要求：只返回 JSON 数组，不要额外解释
- JSON 格式示例：`["chunk_id_3", "chunk_id_1", "chunk_id_4", "chunk_id_2"]`

**Prompt 结构：**
```
You are a relevance ranking expert. Your task is to rerank the retrieved document chunks...

## Query
{query}

## Retrieved Chunks
{chunks}

## Instructions
1. Analyze each chunk's relevance to the query
2. Consider semantic similarity, factual correctness, and completeness
3. Rank the chunks from most relevant (1) to least relevant
4. Return ONLY a JSON list with the ranked chunk IDs

## Output Format
Return ONLY a JSON array like this:
```json
["chunk_id_3", "chunk_id_1", "chunk_id_4", "chunk_id_2"]
```
```

### 2. `src/libs/reranker/llm_reranker.py`
**作用：** 基于 LLM 的智能重排序实现

**关键内容解读：**
- **LLMReranker 类**：继承 BaseReranker，实现 LLM 驱动的重排序
  - `top_k`: 返回的最大候选人数
  - `model`: 使用的 LLM 模型名称
  - `prompt_path`: Prompt 模板文件路径（默认：config/prompts/rerank.txt）
  - `custom_prompt`: 自定义 prompt（覆盖文件，便于测试）

- **核心方法：**
  - `_load_prompt_template()`: 从文件加载 prompt，支持自定义覆盖，如果文件不存在或内容为 TODO 则使用内置 DEFAULT_PROMPT
  - `rerank(query, candidates, **kwargs)`: 主逻辑
    1. 验证输入（非空 candidates、必需 settings）
    2. 构造 prompt（`_construct_prompt`）
    3. 调用 LLM（通过 LLMFactory）
    4. 解析响应（`_parse_llm_response`）
    5. 重排序 candidates 并更新分数
    6. 失败时降级到原始顺序
  - `_construct_prompt(query, candidates)`: 格式化 prompt
    - 将每个候选人的 id、content、metadata、score 格式化为文本
    - 替换模板中的 `{query}` 和 `{chunks}` 占位符
  - `_parse_llm_response(response)`: 提取 JSON 数组
    - 策略 1：正则匹配 ```json...``` 或 ```...``` 代码块
    - 策略 2：正则匹配方括号 `[...]` 数组
    - 策略 3：传统字符串分割处理
    - 验证返回值是列表，转换为字符串数组

- **降级机制：**
  - LLM 调用失败：捕获异常，返回原始顺序
  - JSON 解析失败：捕获 ValueError，返回原始顺序
  - 返回 `fallback_triggered=True` 标志

- **分数计算：**
  - 基于排名位置计算新分数：`new_score = 1.0 - (rank / total)`
  - 第 1 名分数 ≈ 1.0，最后一名分数 ≈ 0.0
  - 创建新的 RerankCandidate 实例（不可变更新）

## 🔑 关键设计解读

### Q1: 为什么要使用 Prompt 模板文件？
**解释：** Prompt 模板定义了 LLM 如何进行重排序，包括任务描述、输入格式、输出要求。将模板放在配置文件中便于修改和 A/B 测试，无需修改代码。

**优点：**
- Prompt 工程优化时不需要重新部署代码
- 不同场景可以定制不同的 Prompt（如中文、英文、特定领域）
- 便于测试和迭代
- 支持 `custom_prompt` 参数进行单元测试

**文件位置：**
- 生产环境：`config/prompts/rerank.txt`
- 测试环境：通过 `custom_prompt` 参数注入

### Q2: 为什么要实现三层 JSON 解析策略？
**解释：** 不同 LLM 对 Prompt 的响应格式不同，有些会包含 Markdown 代码块，有些是纯文本，有些会有额外解释。我们需要健壮的解析逻辑处理各种情况。

**解析策略（按优先级）：**
1. **正则匹配代码块**：````json\n[...]\n```` 或 ```\n[...]\n```
2. **正则匹配方括号**：`\[.*?\]`（re.DOTALL 模式）
3. **传统字符串分割**：处理 ````json`、``` ` 等标记

**示例处理：**
```python
# 输入 1：纯 JSON
["chunk3", "chunk1", "chunk2"]

# 输入 2：Markdown 代码块
Here are the ranked chunks:
```json
["chunk3", "chunk1", "chunk2"]
```
The ranking is based on relevance.

# 输入 3：无语言标记的代码块
```
["chunk3", "chunk1", "chunk2"]
```
```

### Q3: 为什么要实现降级机制（Fallback）？
**解释：** LLM 调用可能会失败（API 错误、超时、限流）或返回不符合预期的结果。降级机制确保即使失败，用户仍能获得结果（原始排序顺序），而不是完全崩溃。

**降级触发条件：**
- LLM API 调用失败（网络错误、认证失败）
- JSON 解析失败（格式错误、非列表类型）
- 其他未预期异常

**降级行为：**
- 返回原始候选人顺序
- 保持原始候选人分数
- 设置 `fallback_triggered=True` 标志
- 记录警告日志

**类比：** 汽车的备胎系统，如果爆胎了可以临时用备胎继续行驶，虽然不如正常轮胎，但至少能继续前进。

### Q4: 为什么要创建新的 RerankCandidate 实例而不是直接修改 score？
**解释：** 数据类（dataclass）虽然是可变的，但创建新实例更符合函数式编程原则，避免副作用（side effects），使代码更易于理解和测试。

**不可变更新模式：**
```python
# ❌ 可变更新（不推荐）
candidate.score = new_score
ranked_candidates.append(candidate)

# ✅ 不可变更新（推荐）
updated_candidate = RerankCandidate(
    id=candidate.id,
    content=candidate.content,
    score=new_score,  # 新分数
    metadata=candidate.metadata
)
ranked_candidates.append(updated_candidate)
```

**优点：**
- 避免意外修改原始数据
- 更容易追踪数据流
- 测试时更可靠（不会影响其他测试）

### Q5: 分数计算公式为什么是 `1.0 - (rank / total)`？
**解释：** 这个公式确保：
- 第 1 名：`score ≈ 1.0`（最高分）
- 最后一名：`score ≈ 0.0`（最低分）
- 分数范围：`(0.0, 1.0]`（开区间）

**示例（3 个候选人）：**
- 排名 1：`1.0 - (0/3) = 1.0`
- 排名 2：`1.0 - (1/3) ≈ 0.67`
- 排名 3：`1.0 - (2/3) ≈ 0.33`

**优点：**
- 分数与排名强相关（排名越前，分数越高）
- 分数归一化到 [0, 1] 区间
- 易于与其他分数（如向量相似度）比较

## 🔧 使用示例

### 基本使用
```python
from src.libs.reranker.llm_reranker import LLMReranker
from src.libs.reranker.base_reranker import RerankCandidate

# 创建 LLMReranker
reranker = LLMReranker(
    top_k=5,
    model="gpt-4o",
    prompt_path="config/prompts/rerank.txt"
)

# 准备候选人（来自检索结果）
candidates = [
    RerankCandidate(
        id="chunk1",
        content="Machine learning is a subset of artificial intelligence...",
        score=0.85,  # 原始向量相似度分数
        metadata={"source": "textbook.pdf", "page": 42}
    ),
    RerankCandidate(
        id="chunk2",
        content="Deep learning uses neural networks with multiple layers...",
        score=0.78,
        metadata={"source": "paper.pdf", "page": 3}
    ),
    RerankCandidate(
        id="chunk3",
        content="The history of ML dates back to the 1950s...",
        score=0.72,
        metadata={"source": "article.html"}
    ),
]

# 重排序
result = reranker.rerank(
    query="What is machine learning?",
    candidates=candidates,
    settings=settings  # 需要包含 LLM 配置
)

# 检查结果
print(f"Method: {result.method}")  # "llm"
print(f"Fallback: {result.fallback_triggered}")  # False
print(f"Top candidate: {result.candidates[0].id}")  # "chunk1" (最相关)
print(f"New score: {result.candidates[0].score}")  # ~1.0 (基于排名)
```

## 📝 技术亮点

### 1. 健壮的 JSON 解析
- 三层解析策略（代码块 → 方括号 → 字符串分割）
